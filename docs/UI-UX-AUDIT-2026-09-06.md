# SteerLab SwiftUI app — UI/UX audit (2026-09-06)

Read-only audit of `Sources/SteerLabApp` at main `73bfbd7`. No code was edited. Every file path below is relative to `Sources/SteerLabApp/` unless it starts with `ExperimentKit/`.

## 1. Scope and method

- **Static review.** All 100 files / 42,360 lines were read line-by-line by twelve parallel reviewers, one per screen cluster, against one shared checklist (tooltip coverage, button correctness, view/state bugs, design consistency, accessibility). Each reviewer cross-checked action closures against the ExperimentKit stores they call. The twelve cluster reports (`01`–`12`) live in `docs/ui-ux-audit-2026-09-06/` and carry the exhaustive per-control "missing tooltip" lists and coverage tables.
- **Cross-cutting greps** over the whole app target: old section names in string literals, internal codenames, swallowed errors, sheet keyboard hygiene, clipboard feedback, `minHeight` in split columns, dangling doc references.
- **Live pass.** A scratch workspace was minted with `steerlab-cli workspace init`; only the app's persisted `SteerLabWorkspaceRoot` was pointed at it (restored afterwards; the real study workspace was never opened). Walked every section, sub-tool, toolbar menu and the New Study flow, first on the installed `0.9.5+b6949ff` bundle, then on a fresh Release bundle built from main with `scripts/build-app.sh`. No connect, submit, or cluster action was triggered. The repo tree is unchanged.

## 2. Headline findings (fix these first)

1. **[BUG, live] The window restores narrower than its declared minimum and the controls pane collapses below its floor.** `SteerLabApp.swift:131` declares `minWidth: 1200`; the app restored at ≈1140 pt. Inside it, `ChatView.swift:94-101` gives the viewer `layoutPriority(1)` and the controls pane `minWidth: section.minimumContentWidth` (560), but the `HSplitView` honours its persisted divider position over that minimum: the controls pane rendered at ≈444 pt both in the small window and after zooming to 1372 pt. Visible damage: the Results header (`SectionContainers.swift:697-723`, an `HStack` of title + caption + Explorer button + Type picker + a fixed-220 pt filter field + Refresh, ≈800 pt wide) wrapped to "Run directo-ries", "Typ e", "Resu…", "Refr…" until the divider was dragged past ≈600 pt. The Playground compute caption (`ChatView.swift:1168-1176`) and Data inventory names/kinds (`DatasetInventoryView.swift:252-268`, middle-truncated with no `.help` carrying the full name) truncate at the same widths. Fix: enforce the section minimum against the persisted divider (reset the divider when the controls pane is under its floor), make the Results header two rows / flexible, and add `.help` on truncating text.
2. **[BUG, live] A freshly created study immediately shows the stale-draft warning.** After "New Study" the Study Setup section reads "The saved study changed since these fields were loaded. Reload and review it before saving." with a "Discard edits and reload" button, before any edit. Cause: `ExperimentKit/StudyManagementController.swift:81-88` returns `true` whenever `authoringReview` is nil, and `newStudy` (called from `StudyManagementSection.swift:277`, which then auto-opens Rename at `:304`) creates and selects the draft without beginning its review. Fix: call `beginAuthoringReview(named:)` after create (and after Rename/Duplicate).
3. **[BUG] Pressing Return in the Playground composer destroys the typed text when the send is refused.** `ChatView.swift:925-937` clears `draft` and `stagedLongPrompt` before `service.send`/`seedAssistantTurn`, and `PromptInputTextView.keyDown` (`:2858-2870`) submits without the buttons' disabled predicate; `ChatService.send`/`seedAssistantTurn` early-return on `turnConstraintReason`/`seedUnavailableReason`, leaving only the red banner. Fix: guard `sendDraft` on the same predicates, or clear only after acceptance.
4. **[BUG] The optimize composer declares a study before validating the grid, minting orphan drafts.** `OptimizationComposerView.swift:1075-1121` only checks that the layer/alpha fields parse; the real audit (`ExperimentStore.sweepGridProblem`) runs after `ExperimentStore.create` has written the manifest, so a fraction of 1.2 or a descending ladder yields "created with its pins but without the declared criterion" plus an "already exists" refusal on retry. `SweepSpecForm.validate` is public and unused here. Same screen: "Declare & Optimize" (`:1027-1041`) silently does not start the sweep when another local sweep is running, and on an unpaired server it declares, switches region, then refuses.

## 4. Cross-cutting patterns

- **Explanation placement.** The 2026-07-19 usability programme introduced `InfoButton` as the primary explanation layer with hover help as secondary. It is used in Studies, Pipelines, Readiness and the templates sheets, and nowhere in Concepts, Optimizations, Multi-Agent, Compute, Cluster, Analysis, Playground. Several gates and refusals exist only as tooltips (listed under headline 24).
- **Refusal placement.** Panels that render refusals beside the control (`seatCastingRefusal`, `declareDisabledReason`, `extractDisabledReason`, `sweepDisabledReason`, the composer's per-button reasons) read well; panels that route to `panel.note` land the message in a Status section at the bottom of a long Form and the bell (Adapter Training, Create Agent, Copy JSON, Create Draft, Rename behind a sheet).
- **Help-string convention.** The lowercase-fragment convention holds in most files; `FineTuningPanelView`, `MultiAgentPanelView`, `StudyControlCopy`, parts of `ChatView`, `ServerJobsPanelView`, `StudySetupSection` use sentence case with periods. Backticks appear literally in seven `+`-concatenated strings and tooltips.
- **Raw values in copy.** `rawValue` enums (`ExtractionMethod`, `topology`, run status, lifecycle chip), manifest keys (`promotedBy: manualOverride`, `orderFlipped`), CLI verbs without the product name, JSON field names, and the internal type name "Workspace" on the Compute picker.
- **Layout at the floors.** Beyond the Results header, eleven non-wrapping `HStack` action rows exceed the 560 pt controls minimum (Concepts ×5, Agents ×3, Compute keys rows, J-lens ×2, Home next-actions at 420). The window floor of 1200 is over-committed by 20 pt when the sidebar is at its 240 max.
- **Nested vertical scrolling.** Agent roster, J-lens table, wizard transcript/preview panes, site editor previews, coauthoring sheet panes.
