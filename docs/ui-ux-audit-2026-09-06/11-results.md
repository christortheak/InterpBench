## Extra-item verdicts (a)–(f)

- **(a) run immutability** — Verified: no control in this cluster writes into an existing run directory. `Analyze` → `ExperimentTasks.analyze` → `StudyAnalysisWorkflow.analyze` writes a NEW analyze run (caption says so, L554–556). `Import Evidence` downloads to `.steerlab/downloads/<uuid>` and lands a NEW `runs/<imported>` (ExperimentPanel.swift:1508–1543); its `.help` states the effect. The explorer bridge (`ResultsExplorerBridge.tree/fileData`) is read-only. The only soft path to mutation is `NSWorkspace.shared.open(file.url)` (L1027, L1085) which hands an immutable file to an editor — and L1087 draws it with a **pencil** icon. Labelling gap: "Open in Finder" (L930) actually *reveals* (selects the folder in its parent).
- **(b) large-file previews** — Bounded (JSON ≤ 1 MiB whole-parse gate, CSV 128 KiB head, JSONL 256 KiB head, text 4 KiB head; remote 4 MiB report cap). Truncation is labelled, but the label is wrong for remote and the viewer-side preview box has no open-externally affordance (see findings 1, 13).
- **(c) charts** — α axis correctly says "residual-norm units". No tooltips on any point; forest Δ axis and dose "effect" axis carry no metric/unit; single-series dose chart shows no legend so the (concept, layer) identity is invisible; NaN guarded (forest `isFinite`, dose filtered upstream); series colour-only (mitigated by legend only when >1 series).
- **(d) remote parity** — Same filters/Refresh/Type picker and same row line. Divergences: previews render inline in the controls pane instead of the viewer; remote file rows are not focusable; no loading state on the listing; errors only in a truncated one-line caption; exclusions section silently absent for server runs.
- **(e) results explorer** — Opens an embedded WKWebView SPA in a 1180×780 sheet; labelled with the run name; Done + Esc. No loading/error state inside the sheet; remote variant's disabled reason is hover-only.
- **(f) selection sync** — Local list → `service.selectedResultsRun` → viewer works, and deselect clears the focused file. Gaps: switching source to "On server" leaves the local selection driving the viewer until a server run is clicked; Refresh does not reload the selected run's file list.

## Findings

- **[BUG]** `SectionContainers.swift:1198`, `:1234`, `:1292` — CSV/JSONL/Text truncation captions "first N rows — open in Finder for the full table", "first N records — open in Finder for the full file", "head only — open in Finder for the full file" — `RunFilePreviewBox` is the ONE renderer and is also used for **server** previews (`RemoteRunDetailView` L1556–1559, fed by `StudyResultsState.loadRemoteRunDetail`), where no local file exists and Finder can show nothing. For local files "open in Finder" does not open a file either (it reveals). — Caption should be preview-kind neutral ("preview shows the first N rows; use Quick Look / open in default app for the whole file") and, for remote, "the full file stays on the server — Import Evidence to read it locally". Also `RunResultsViews.swift:1391` uses yet a third wording ("open the file for the full table").
- **[BUG]** `SectionContainers.swift:1457–1470` — remote empty state — There is no loading state for the server listing: while `isLoadingRemoteResults` is true and `runs` is empty (every first load, every source switch since `.task` at L1322 refetches) the pane shows "No server runs listed — Connect to <server> to browse its immutable runs/ tree read-only." although the app IS connected and fetching. After a transport failure the same view says "This unpaired server reported nothing to browse. could not reach <server> — …" which conflates "empty" with "failed". — Show a `ProgressView` + "fetching runs from <server>…" while loading, and an error-styled `ContentUnavailableView` on failure.
- **[BUG]** `SectionContainers.swift:1354–1367` — remote header caption (`headerCaption`) — Every remote error (listing failure, per-file fetch failures "run X: could not fetch report.json (…); generations.jsonl (…) — and 3 more", import failures) is rendered ONLY here, `.lineLimit(1)` + `.truncationMode(.middle)`, no `.help`, no `textSelection` — the reason is cut out of the middle and cannot be read or copied. In the detail pane a fetch failure is invisible: the failed file silently drops into "Other files" (L1666–1685 shows name+size only; the `"fetch failed: …"` reason computed in `StudyResultsState.swift:267` is discarded). — Give status its own multi-line, selectable row (error-tinted), and show the per-file reason on remote "Other files" rows.
- **[BUG]** `SectionContainers.swift:1577–1588` — "Import Evidence" — Async download + verify + extract with no busy indicator and no re-entry guard: the button stays enabled while `importEvidence(fromServerRun:)` runs, so a double-click starts two downloads into two `.steerlab/downloads/<uuid>` dirs and two imports. Progress/failure is a `.lineLimit(1)` caption (L1603–1610) that only appears when the status text happens to contain "evidence"; "evidence import failed: \(error)" is raw and truncated. — Disable while importing, show `ProgressView`, render the outcome selectable and unclipped.
- **[BUG]** `RunResultsViews.swift:627–629` — "Analyze (local)" success message "analysis → <dir> — refresh the run list to browse it" — The action creates a new run directory but nothing rescans `ResultsPanelView.items` (only Refresh L715 / onAppear L671 do); the researcher must find the Refresh button in the header. Same for the server path (L649–650 "then refresh the server runs list"). — Trigger the rescan (and select the new run) from the finished state.
- **[BUG]** `SectionContainers.swift:758–762` and `:1427–1431` — `VSplitView { runList.frame(minHeight: 140) ; detailPane.frame(minHeight: 200) }` — The split with fixed minimum heights is mounted only when the list is non-empty (`items.isEmpty ? emptyState : browser`, L665; `runs.isEmpty` L1327); `items` fills in `.onAppear` (L671) and `runs` fills asynchronously in `.task` (L1322), and toggling the segmented source swaps the whole subtree (L638–643). The controls column (an `HSplitView` column, ChatView.swift:93–99) therefore changes its SwiftUI minimum height 0 → 340 after first layout / on async state — the known fatal class on this macOS beta. (unverified — cannot run; flagged per checklist.) — Keep the split mounted with the empty state overlaid, or drop `minHeight` from the split children.
- **[BUG]** `SectionContainers.swift:965–985` — `RunDetailView.load()` — Called synchronously from `.onAppear`/`.onChange` on the main actor; for EVERY top-level file it calls `RunBrowser.preview(for:)` just to decide previewability (whole-parse of any JSON up to 1 MiB, 256 KiB JSONL and 128 KiB CSV heads, per file), then the viewer parses the focused file AGAIN (`ActivityFeedColumn.swift:324`). `rescan()` (L806) likewise reads up to 300 `config.json` stamps on the main actor. A run with many artifacts hitches the UI on selection. — Classify by extension/size (cheap) and do the parse once, off the main actor (`Task.detached` as `RunSemanticSectionsView` already does at RunResultsViews.swift:209).
- **[DESIGN]** `SectionContainers.swift:1029` vs `:1095` vs `:1087` — Same icon, different actions in adjacent rows: `arrow.up.forward.square` means "open in default app" in `SelectableRunFileRow` (L1026–1032) but "reveal in Finder" in `OtherFileRow` (L1092–1098); "open in default app" in `OtherFileRow` uses `square.and.pencil` (L1084–1090), a pencil on files the app declares immutable. — One icon per action across both rows: `folder` = reveal in Finder (as L840/L930 already use), `arrow.up.forward.square` = open in default app, `eye` = Quick Look.
- **[DESIGN]** `SectionContainers.swift:930` / `:846` / `:1098` / `RunResultsViews.swift:838` — Four labels for one action (`NSWorkspace.activateFileViewerSelecting`): "Open in Finder", "reveal this run directory in Finder", "reveal in Finder", "Reveal artifacts". - **[DESIGN]** `SectionContainers.swift:697–723` (local header) and `:1338–1348` (remote header) — One `HStack` holding title + caption ("N of M shown · immutable, newest first"), Results Explorer button, Type picker (`maxWidth: 180`), filter field (**fixed** `width: 220`), Refresh ≈ 780–820pt at the section's 560pt minimum (`WorkbenchSection.minimumContentWidth`). ## Notes on strengths

- Preview bounds are real and shared: one parser (`RunBrowser`), one renderer (`RunFilePreviewBox`), size-gated JSON, head-only CSV/JSONL/text, remote heads capped server-side — no path slurps a multi-GB generations file.
- The semantic stack (`RunSemanticSectionsContent`) is one view for all three surfaces, absent-artifact tolerant, with honest labelling of head-derived vs whole-run numbers and stamped vs recomputed agreement.
- Every immutable-run action is a "new directory" action (analyze, import) and says so; the explorer bridge refuses symlinks and path escapes.
- Chart NaN handling and the CI-bar `accessibilityLabel` show care; the validation table's neutral band around chance avoids false-precision colouring.
